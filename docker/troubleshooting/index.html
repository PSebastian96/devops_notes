    Troubleshooting

    Docker Troubleshooting

    A useful Docker troubleshooting process is:

    Problem
  │
  ├── Container running?
  ├── Image correct?
  ├── Logs?
  ├── Network?
  ├── Ports?
  ├── Environment?
  ├── Volumes?
  └── Resources?

    Docker Daemon Not Running

    Check:

    docker info

    Linux:

    sudo systemctl status docker

    Start:

    sudo systemctl start docker

    Enable at boot:

    sudo systemctl enable docker

    Permission Denied

    If you see:

    permission denied while trying to connect to the Docker daemon socket

    Check:

    groups

    Add your user:

    sudo usermod -aG docker $USER

    Then log out and back in.

    Container Exits Immediately

    Check:

    docker ps -a

    Then:

    docker logs <container>

    Inspect:

    docker inspect <container>

    The most common cause is that the container's main process has exited.

    Container Keeps Restarting

    Check:

    docker ps

    Then:

    docker logs <container>

    Inspect restart configuration:

    docker inspect <container>

    Look for application crashes, configuration errors, failed health checks, or missing dependencies.

    Port Already in Use

    If Docker reports:

    Bind for 0.0.0.0:8080 failed: port is already allocated

    Find what is using the port on Linux:

    sudo ss -ltnp | grep :8080

    Or change the host port:

    docker run \
  -p 8081:80 \
  nginx

    Container Cannot Reach Another Container

    Check the networks:

    docker network ls

    Inspect:

    docker network inspect <network>

    Ensure both containers are connected to the same user-defined network.

    Within Compose, use the service name:

    db:5432

    not:

    localhost:5432

    Container Cannot Reach Internet

    Check:

    docker exec -it <container> sh

    Then test DNS:

    getent hosts example.com

    Check network configuration:

    docker inspect <container>

    Image Won't Build

    Build without relying on cache:

    docker build --no-cache -t my-app .

    Use verbose build output:

    docker build --progress=plain -t my-app .

    Check:

    • Dockerfile syntax
    • Build context
    • .dockerignore
    • Package repositories
    • Network connectivity
    • Base image availability

    File Not Found During COPY

    If:

    COPY something.txt /app/

    fails, verify that the file exists inside the build context.

    For:

    docker build .

    Docker can only access files below the current build context.

    Check .dockerignore.

    Container Has No Data

    Check mounts:

    docker inspect <container>

    Look under:

    Mounts

    List volumes:

    docker volume ls

    Inspect:

    docker volume inspect <volume>

    Check Resource Usage

    docker stats

    Check disk usage:

    docker system df

    Clean Up Disk Space

    Unused containers:

    docker container prune

    Unused images:

    docker image prune

    Unused networks:

    docker network prune

    Unused volumes:

    docker volume prune

    General cleanup:

    docker system prune

    Danger

    Cleanup commands can delete resources you may still need.

    Compose Troubleshooting

    Check configuration:

    docker compose config

    List services:

    docker compose ps

    View logs:

    docker compose logs

    Follow logs:

    docker compose logs -f

    Rebuild:

    docker compose build --no-cache

    Restart:

    docker compose down
docker compose up -d

    Useful Diagnostic Sequence

    When a container isn't working:

    docker ps -a

docker logs <container>

docker inspect <container>

docker stats

docker network ls

docker volume ls

    For Compose:

    docker compose ps

docker compose logs

docker compose config

docker compose images

    This usually narrows the problem down to one of:

    Image
  │
  ├── Build problem
  ├── Configuration
  ├── Application
  ├── Networking
  ├── Storage
  ├── Permissions
  └── Resources
